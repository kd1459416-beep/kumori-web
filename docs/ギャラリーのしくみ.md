# ギャラリーのしくみ

`/fog` でシャッターを押してから、ギャラリーに写真が並ぶまでの流れを、コードを追いながら説明します。
VS Code で左にこのファイル、右にコードを開いて、行番号を見比べながら読むのがおすすめです。

---

## 全体の流れ

1. `/fog` で右下のシャッター（または S キー）を押す
2. ブラウザが、いま画面に映っている絵を PNG 画像にする
3. その画像を Flask サーバーの `/api/photos` に送る（POST）
4. Flask が `photos/` フォルダに保存し、一覧用の小さい画像（サムネイル）を `photos/thumbs/` に作る
5. `/gallery` を開くと、Flask が `photos/` の中身を調べて一覧の HTML を作って返す
6. 写真を押すと大きく表示され、そこから保存・削除ができる。削除はブラウザが `/api/photos/写真の名前` に DELETE を送る

役割分担はこうです。

- **ブラウザ（JavaScript）**：絵を画像にする、サーバーに送る、画面を動かす
- **サーバー（Python / Flask）**：画像をファイルとして保存する、一覧を作る、消す

### toast()：お知らせを数秒だけ出す

```js
let toastTimer = 0;
function toast(text, withLink) {
  $('toastText').textContent = text;
  $('toastLink').hidden = !withLink;
  $('toast').classList.add('show');
  clearTimeout(toastTimer);
  toastTimer = setTimeout(() => $('toast').classList.remove('show'), 4000);
}
```
- 文字を入れる（`textContent` を使うと、文字が HTML として解釈されないので安全です）
- `withLink` が `false` なら「見る」リンクを隠す
- `show` を付けて表示する（CSS で下からふわっと出てくる）
- 前のタイマーが残っていたら取り消して、新しく「4秒後に消す」タイマーをセットする。連続でシャッターを押しても、最後に押してから4秒は表示されたままになります

## 2. app.py：サーバー側

### 最初の準備（20〜29行目あたり）

```python
PHOTO_DIR = BASE_DIR / "photos"
THUMB_DIR = PHOTO_DIR / "thumbs"
THUMB_DIR.mkdir(parents=True, exist_ok=True)
```
「写真の置き場所は `photos`、サムネイルはその中の `thumbs`。フォルダがなければ作る」。
`parents=True` は「途中のフォルダ（`photos`）もなければ一緒に作る」、`exist_ok=True` は「もうあってもエラーにしない」という意味です。

```python
NAME_RE = re.compile(r"^\d{8}-\d{6}-[0-9a-f]{6}\.png$")
```
「写真の名前のルール」を正規表現で決めています。読み方は次のとおりです。
- `^` … 先頭から
- `\d{8}` … 数字8つ（20261126 ＝ 年月日）
- `-` … ハイフン
- `\d{6}` … 数字6つ（101530 ＝ 時分秒）
- `[0-9a-f]{6}` … 0〜9 か a〜f が6つ（ランダムな文字）
- `\.png$` … 最後が `.png` で終わる

**なぜ必要か**：削除の URL は `/api/photos/写真の名前` です。もしルールがないと、誰かが `/api/photos/../app.py` のような名前を送って、写真以外のファイルを消そうとするかもしれません。ルールに合わない名前はすべて門前払いにしています。

### 51行目 `check_name()`：名前の検査係

```python
def check_name(name):
    if not NAME_RE.match(name):
        abort(404)
    return name
```
「名前がルールに合わなければ、『見つかりません（404）』で処理を打ち切る。合っていればそのまま返す」。

### 57行目 `taken_at()`：名前から撮った日時を取り出す

```python
    return datetime.strptime(name[:15], "%Y%m%d-%H%M%S")
```
「名前の最初の15文字（`20261126-101530`）を、『年4桁・月2桁・日2桁-時・分・秒』として読んで、日時にする」。
撮った日時をファイル名に入れておいたので、別にデータベースを用意しなくても日付が分かります。

### 62行目 `list_photos()`：一覧を作る

```python
    names = sorted((p.name for p in PHOTO_DIR.glob("*.png") if NAME_RE.match(p.name)), reverse=True)
```
右から読むと分かりやすいです。
- `PHOTO_DIR.glob("*.png")` … `photos` フォルダの中の `.png` を全部探す
- `if NAME_RE.match(p.name)` … そのうち、名前がルールに合うものだけ
- `p.name for p in ...` … ファイルの名前だけを取り出す
- `sorted(..., reverse=True)` … 名前の逆順に並べる。名前が日時で始まるので、**新しい写真が先頭**になります

```python
    for n in names:
        d = taken_at(n)
        photos.append({
            "name": n,
            "url": f"/photos/{n}",
            "thumb": f"/thumbs/{n.replace('.png', '.jpg')}",
            "date": f"{d.year}年{d.month}月{d.day}日 {d:%H:%M}",
        })
```
「1枚ずつ、名前・大きい画像の URL・サムネイルの URL・表示用の日付をまとめた辞書を作って、リストに足していく」。
`f"..."` は f文字列で、`{ }` の中に変数の値が入ります。`{d:%H:%M}` は「時:分」の形にする書き方です。

### 76行目 `make_thumb()`：サムネイルを作る

```python
    with Image.open(src) as im:
        im = im.convert("RGB")
        im.thumbnail((THUMB_WIDTH, THUMB_WIDTH * 2))
        im.save(dst, "JPEG", quality=82)
```
Pillow（Python の画像ライブラリ）を使っています。
- `Image.open(src)` … 元の PNG を開く。`with` を使うと、使い終わったら自動で閉じてくれます
- `convert("RGB")` … JPEG は透明を持てないので、透明の情報を外す
- `thumbnail((640, 1280))` … 横640・縦1280の箱に収まるように、**縦横の比率を保ったまま**縮める
- `save(..., "JPEG", quality=82)` … JPEG で保存。82 は画質（100が最高）。見た目をあまり落とさずに軽くできる値です

**なぜ必要か**：retina の画面だと、元の PNG は1枚 3〜5MB になります。一覧にそのまま並べると重いので、一覧では数十KBのサムネイルを使い、押したときだけ元の PNG を表示しています。

### 92行目 `api_save()`：写真を受け取って保存する

```python
@app.post("/api/photos")
```
「`/api/photos` に POST が来たら、下の関数を動かす」。fog.html の `fetch` はここに届きます。

```python
    data = request.get_data()
    if not data.startswith(PNG_SIGNATURE):
        return jsonify(error="PNG画像ではありません"), 400
```
「届いた中身を取り出す。先頭が PNG の目印（`\x89PNG...` の8バイト）で始まっていなければ、『PNG じゃないよ』と 400（リクエストがおかしい）で返す」。
PNG ファイルは必ずこの8バイトで始まる決まりなので、画像以外のものを保存しないための入口チェックです。

```python
    name = datetime.now().strftime("%Y%m%d-%H%M%S-") + uuid.uuid4().hex[:6] + ".png"
    (PHOTO_DIR / name).write_bytes(data)
```

「今の日時＋ランダムな6文字＋`.png` を名前にして、`photos` フォルダに書き込む」。
ランダムな文字を足しているのは、同じ秒に2枚撮っても名前がぶつからないようにするためです。

```python

        make_thumb(name)
    except Exception:
        (PHOTO_DIR / name).unlink(missing_ok=True)
        return jsonify(error="画像を読み込めませんでした"), 400
```
「サムネイルを作ってみる。失敗したら（＝先頭だけ PNG で中身が壊れていたら）、保存したファイルを消して 400 を返す」。
`unlink` はファイルを消す命令です。

```python
    return jsonify(name=name, url=f"/photos/{name}", gallery="/gallery"), 201
```
「保存した名前などを JSON で返す。201 は『新しく作りました』という意味の成功の番号」。

### 107行目 `api_delete()`：写真を消す

```python
@app.delete("/api/photos/<name>")

    check_name(name)
```
「`/api/photos/〇〇` に DELETE が来たら動く。`<name>` の部分が引数 `name` に入る。まず名前を検査する」。

```python
    path = PHOTO_DIR / name
    if not path.exists():
        abort(404)
    path.unlink()
    (THUMB_DIR / name.replace(".png", ".jpg")).unlink(missing_ok=True)
```

「ファイルがなければ 404。あれば消して、サムネイルも消す」。サムネイルは `missing_ok=True` なので、なくてもエラーになりません。

## 3. gallery.html：ギャラリー画面（`templates/gallery.html`）

### Jinja の部分（HTML の中の `{% %}` と `{{ }}`）

```html
{% for p in photos %}
<li>
  <button class="card" data-name="{{ p.name }}" data-url="{{ p.url }}" data-date="{{ p.date }}">
    <img src="{{ p.thumb }}" alt="{{ p.date }} の写真" loading="lazy">
```
これはブラウザに届く前に、**Flask（Jinja）が書き換えます**。
- `{% for p in photos %}` … `list_photos()` で作ったリストの1枚ずつについて、くり返す
- `{{ p.name }}` … その写真の名前に置き換わる
- `data-name` など `data-` で始まる属性 … HTML に好きな情報をメモしておける場所。あとで JavaScript から `dataset.name` で読めます
- `loading="lazy"` … 画面に見えるところまでスクロールしてから画像を読み込む。写真が増えても最初の表示が速くなります

### JavaScript の部分

```js
let cards = [...document.querySelectorAll('.card')];
let current = -1;
```
「画面にある写真カードを全部集めて配列にする。いま大きく見ている番号は、最初は -1（どれも見ていない）」。
`[... ]` は、`querySelectorAll` が返す一覧を、ふつうの配列に変える書き方です（配列にすると `splice` などが使えます）。

```js
function show(i) {
  current = (i + cards.length) % cards.length;
```
「i 番目を表示する。ただし端を越えたら反対側に回る」。
たとえば3枚のとき、0番で「←」を押すと i は -1 になります。(-1 + 3) % 3 = 2 なので、最後の写真に回ります。`%` は割った余りです。

```js
  const c = cards[current].dataset;
  $('big').src = c.url;
  $('bigDate').textContent = c.date;
  $('dl').href = c.url;
  $('dl').download = 'fog-' + c.name;
```
「カードにメモしておいた情報を取り出して、大きい画像・日付・保存ボタンにセットする」。
`download` 属性が付いたリンクは、押すと画面を移動せずにファイルを保存します。

```js
async function remove() {
  const card = cards[current];
  const res = await fetch('/api/photos/' + encodeURIComponent(card.dataset.name), { method: 'DELETE' });
  if (!res.ok) { $('bigDate').textContent = '削除できませんでした'; return; }
```
「サーバーに『この写真を消して』と DELETE を送る。失敗したら、日付の場所にそう表示して終わる」。
`encodeURIComponent` は、名前を URL に入れても安全な形にする関数です。

```js
  card.closest('li').remove();
  cards.splice(current, 1);
  $('count').textContent = cards.length + '枚';
  if (!cards.length) { $('empty').hidden = false; close(); return; }
  show(current);
```
「サーバーで消せたら、画面からもそのカードを取り除く」。
- `closest('li')` … カードを包んでいる `<li>` を探す
- `splice(current, 1)` … 配列から current 番目を1つ取り除く
- 0枚になったら「まだ写真がありません」を出して閉じる
- まだあれば、同じ番号を表示する。取り除いたので、そこには**次の写真**が来ています

### 削除の確認を、画面の中でしている理由

`confirm()`（ブラウザ標準の「OK / キャンセル」の小窓）を使わずに、「本当に削除する？」をボタンで出しています。
標準の小窓は見た目を変えられず、fog の雰囲気と合わないためです。

```js
$('del').onclick = () => { $('del').hidden = true; $('confirm').classList.add('show'); $('yes').focus(); };
```
「削除ボタンを隠して、『本当に削除する？ ／ 削除する ／ やめる』を出し、『削除する』にフォーカスを移す」。
